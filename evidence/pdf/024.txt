perp-maker’s ask is rounded DOWN to the tick, so on coarse- tick markets the sell quote lands at or below the mark

Severity: normal
Area: SDK

 Steps to reproduce

   1. Read the quote path: strategies/perp-maker/src/index.ts:142-143 builds askPx = mark * (1 + half
      - skew) , then placePerp sends alignPrice(adjusted, …) ( packages/perp-core/src/orders.ts:159 ),
      and alignPrice is (price / tick) * tick ( packages/perp-core/src/markets.ts:149 ). It floors for both
      sides; no side is passed.
   2. Take XLM-PERP’s live params on Hideki (tickSize 0.0001; tick ≈ 5.9 bps of the ~0.169 mark; ADA-
      PERP is 5.2 bps, PUMP 2.4, WLD 2.5).
   3. Run the perp-maker math through the real alignPrice , from strategies/perp-maker : npx tsx maker-
      ask-sweep.mts (script at evidence/candidates/kit20-23/maker-ask-sweep.mts ). It uses the default
      PERP_MM_HALF_SPREAD_BPS=15 , PERP_MM_INVENTORY_SKEW_BPS=10 , inventory at the cap (lean = +1, so
      only the ask is quoted and it should sit 5 bps above the mark), and then
      PERP_MM_HALF_SPREAD_BPS=3 with no inventory.
   4. Read-only check against the live markets: NETWORK=hideki DRY_RUN=true npx tsx k20.mts (same
      scratch folder) prints the dry-run quote line for each market.

 Expected

A maker’s sell price rounds UP to the tick and its buy price rounds DOWN, so rounding only widens the
quote and never moves it toward or through the mark. The SDK’s own reference says the same: “A buy
price rounds down, a sell price rounds up” (Somnia Markets TypeScript reference, units-and-scales). The
kit’s own spot example does it too ( examples/02-modular-typescript/src/utils/price.ts:39 : bid floor, ask
ceil).

 Actual

The ask is floored, so up to one whole tick of the intended edge is lost. On XLM that tick is bigger than
the 5 bps the default config leaves on the ask at full inventory, so the ask lands below the mark:

 defaults (half 15bps, skew 10bps), inventory at +cap: ask sent BELOW the mark in 155/1000 marks
 (0.1689..0.1690 step 1e-7), worst -0.92 bps
 PERP_MM_HALF_SPREAD_BPS=3, flat: ask sent BELOW the mark in 493/1000 marks (0.1689..0.1690 step 1e-7),
 worst -2.92 bps
 example mark=0.16891 intended ask=0.1689945 sent ask=0.1689


At the live marks, the default lean-long ask meant to be +5.0 bps went out at +0.78 bps on XLM, +1.61
on ADA, +4.72 on PUMP and +4.19 on WLD ( [dry-run] would place quote short 54 XLM @ 0.169 , live
mark 0.16898674). A ceil would have sent 0.1691. The bid is floored too, which is the right way for a
bid, so the spread is skewed toward selling cheap. When the ask is under the best bid, POST_ONLY
reverts and the quote is skipped. When it is not, the bot rests a sell below fair value.
